# diag 降噪设计：语法豁免 + 编辑静默 + 冷却期（v1.0.10，首个触达学生的降噪版本）

- 日期：2026-11-06 初稿；2026-11-13 基于公网真实数据修订
- 状态：修订稿（待评审）
- 关联：原一期存活窗口设计 `docs/superpowers/plans/2026-10-28-diag-persistence-window-and-event-trim.md`；实现位于 `src/events/diagnosticsListener.ts`
- 用户拍板（2026-11-13）：①合并叙事——一期从未触达学生，三道闸版本（1.0.10）作为学生拿到的第一个降噪版本直接上线；②闸门一采用 d.code 主判别 + 中英双语正则兜底；③公网分发走服务器自托管 vsix

## 1. 背景

### 1.1 一期存活窗口已实现但从未触达公网学生（2026-11-13 数据发现）

一期降噪（PERSIST_MS=30s 存活窗口，指纹=起始位置+消息）已于 2026-10-28 实现并包含在 1.0.8（10-29 出包，已验证 c2e1c9e ⊇ 1b02d67），但**从未有效到达公网学生端**：1.0.8 本身无自更新能力；marketplace publisher 10-29 建失败；服务端云分发清单（`/api/pylearner/latest`，1.0.9）11-02 才部署——而自更新逻辑是 1.0.9 才内置的，卡在学期初装机（1.0.2/1.0.4 时代）的学生没有触发点（自更新引导缺口：新通道只够得着已经在新版上的学生）。

三条独立证据相互印证（公网服务器 trace_events，10-29~11-12）：

1. **代码判据**：新版 `reconcile` 仅在 `snap.fps` 非空时上报，`errors=0` 事件在新版代码下不可能产生；旧版（去抖 1.5s + 计数变化即报）会发 `errors=0`（纯警告/清零事件）。
2. **数据**：15 天共 9153 条 diag，其中 4467 条（48.8%）`errors=0`；23 名学生中 19 名发过 `errors=0` → 全部仍在跑旧版扩展。仅 4 人呈现新版行为（王开/张财谦 10-29，为开发者测试机；张俊南 + 江丽娜家用机 11-10 起共 12 条）。
3. **事件率**：活跃日人均 diag 事件量 10-27 为 136 条、11-07 为 131、11-08 为 132——部署前后完全持平；11-11/12 的下降仅为活跃度下降。

这一发现的双重意义：①分发是本方案生效的**先决条件**（见 §7）；②旧版全量数据构成了完整的未降噪基线，使三道闸的效果可以用真实数据量化验证（见 §6）。

### 1.2 误报主体与数据占比

| 场景 | 现状链路 | 数据占比（10-29~11-12，9153 条） |
|---|---|---|
| 纯警告/清零事件 | 旧版按计数变化上报，warnings 变化也报 | 4467 条（48.8%）——升级到新版后自然消失，无需新增闸门 |
| 打字中间态语法错误 | 边写边产生，停顿超 30s 即报 | errors>0 的 4686 条中约 76% 为纯语法类 |
| 错误随打字演变 | 指纹（行号+消息）随编辑漂移，重新计时连报 | 冷却期可再抑制 569 条 |
| 真语义错误（保留目标） | 如 Undefined name | 幸存样本中占 18.5%，是教师真正需要关注的信号 |

危害：每条 diag 触发一次 LLM 解释调用；diag 推高服务端 `consecutiveErrors`/同类重复计数，把「正在写代码」的学生点亮成黄/红并挤占急需帮助告警位。

## 2. 目标与非目标

**目标**

- diag 事件源头降噪，误报大幅减少（对旧版全量数据模拟保留率约 6%，见 §6）。
- 更精准：幸存事件以语义错误为主，真实反映学生卡点。
- 仅改 `src/events/diagnosticsListener.ts`（及测试/mock），事件类型、服务端协议零改动；payload 仅新增可选字段（见 §4.4），向后兼容。

**非目标（明确不做）**

- 不改服务端状态评分/告警策略。
- 不恢复 edit 事件上报（编辑信号仅作本地内存时间戳，永不落盘、永不上报）。
- 不改 run 事件采集（run 失败是真实信号，保持即时上报）。
- 不在扩展内实现自动更新检查（分发依赖 §7 的自托管渠道 + 教师引导）。

**触达验收指标（服务器 SQL 可验证）**

| 指标 | 升级前（基线） | 升级后预期 |
|---|---|---|

## 4. 设计：三道闸

三道闸按序过滤，任一命中即不上报（或推迟上报）。

### 4.1 闸门一：语法类诊断豁免（永不报）

**理由**：还没写完的误报几乎全是语法类诊断（实测占 errors>0 事件的 76%）。这类错误学生真按 F5 运行时会被 run 失败事件天然覆盖（runListener 解析 traceback 上报），diag 里再报一遍纯属重复噪音。

**判别方案（2026-11-13 拍板：d.code 主判别 + 消息正则兜底）**：

`code` 是机器可读规则码，**与学生电脑的 VS Code 语言包无关**——中文学生和英文学生的同一条诊断 code 相同。原设计稿的纯英文正则方案在真实数据中仅命中 4%（学生主流为中文语言包，`"(" 未关闭`、`应为表达式`、`意外缩进` 全部漏匹配），故降级为兜底。

```ts
/** 已知语法类规则码（Pyright 语法解析错误）；语义类为 report* 系列，不在表内 */
const SYNTAX_CODES = new Set(["invalid-syntax"]);

function isSyntaxLike(d: vscode.Diagnostic): boolean {
  const code = typeof d.code === "object" ? String(d.code?.value ?? "") : String(d.code ?? "");
  if (code) return SYNTAX_CODES.has(code);      // 有码按码判：未知码 → 非语法（保守上报）
  return SYN_PATTERNS.some((re) => re.test(d.message));  // 无码走消息正则兜底（中英双语）
}
```

保守原则：**识别不了的默认按普通错误处理**（漏判只会让该条走后续闸门，不会漏掉真错误）。

**正则兜底表（中英双语，来自 2026-10-29~11-12 公网实测样本，按频次排序）**：

| 模式 | 实测消息示例（频次） |
|---|---|
| `/未关闭/` | `"(" 未关闭`(1486)、`"{" 未关闭`(106)、`"[" 未关闭`(88) |
| `/^应为/` | `应为表达式`(1477)、`应为 ":"`(1151)、`应为缩进块`(815)、`应为 "=" 右侧的表达式`(518) |
| `/语句必须用换行符或分号分隔/` | 同名消息(1127) |
| `/后应为属性名称/` | `"." 后应为属性名称`(541) |
| `/缩进/` | `意外缩进`(362)、`取消缩进量与以前的缩进不匹配`(130)、`不应取消缩进`(123) |
| `/未终止/` | `字符串文本未终止`(175)、`f 字符串中未终止的表达式`(86) |
| `/后应为函数名称/` | `“def”后应为函数名称`(125) |
| `/^Expected\b/i` | `Expected an expression`(245)、`Expected an identifier`(196)、`Expected an indented block after 'elif' clause`(80+) |

| `/^Unexpected\b/i、/was not closed/i、/unterminated/i、/invalid syntax/i、/indentation/i` | 英文变体兜底（设计稿原有） |

模式列表集中在常量区并加注释，后续按实测样本增补（幸存事件持续暴露漏网语法类，增补有数据来源）。

### 4.2 闸门二：编辑静默门槛（存活计时只在「未编辑」时累计）

**理由**：错误在学生持续打字期间产生 = 写作中间态，不具备上报价值；错误在学生停止编辑后仍持续存在 ≥30s，才更像「真卡住」。

**实现**：

- 监听 `vscode.workspace.onDidChangeTextDocument`（仅当 `e.contentChanges.length > 0` 且文件为 .py），该文件 key 下所有现存指纹的 `firstSeen` 重置为当前时刻。
- 语义等价于：**错误必须在最后一次编辑之后静默存活满 PERSIST_MS(30s) 才上报**。学生持续打字 → 计时不断归零 → 永不满足；停笔 30s 后错误仍在 → 上报。
- 纯内存时间戳操作，不产生任何事件、不改 L1Writer。

**与既有语义的合并**：一期存活窗口的指纹生命周期规则（消失清除 firstSeen/reported、消失后再现重新计时）全部保留，编辑重置只是给 firstSeen 增加一个额外的归零触发源。

### 4.3 闸门三：同文件冷却期（抑制指纹演变连报）

**理由**：错误随打字演变（行号漂移、措辞微调）会以新指纹重新走 30s 窗口，同一问题连报多条。

**实现**：

- 每文件记录 `lastReportAt` 与 `lastReportedErrorCount`。
- `reconcile` 命中上报时检查：距 `lastReportAt` 不足 COOLDOWN_MS(120s) 时抑制本次上报，**例外**：当前错误数 ≥ `lastReportedErrorCount + 2`（错误显著恶化）才破例上报。
- 被抑制的指纹仍标记为已报（不重复计时），避免冷却结束后集中补报旧错误。

### 4.4 payload 可选增强：samples 附带 code（服务端零改动）

为在上线后持续验证闸门一覆盖率（幸存事件中是否仍有漏网语法类），上报 payload 新增可选字段 `codes: string[]`（与 samples 一一对应）。服务端原样 JSON 存储、零逻辑改动；旧字段 `errors/warnings/samples` 不变。评审时如认为多余可整体删除，不影响其余设计。

## 5. 降噪后语义汇总

| 状况 | 旧版行为（当前学生实际所处） | v1.0.10 行为 |
|---|---|---|
| 纯警告事件 | 每次警告计数变化即报 | 永不报（只统计 error 级指纹，自然消失） |
| 打字中的语法错误（中间态） | 停顿 1.5s 即报 | 语法豁免（code 判别），永不报 |
| 打字中的运行时类诊断（如未定义变量） | 停顿 1.5s 即报 | 持续打字期间不报；停笔后仍存在 30s 才报 |
| 手误后 10s 内修正 | 报（误报） | 窗口内消失，不报 |
| 手误后停顿 40s（思考） | 报（误报） | 仍会报（静默 30s 满足）；属可接受残留，学生 40s 未动一个错已接近「需要关注」 |
| 同一错误指纹演变连报 | 每个新指纹各报一条 | 冷却 120s 内合并为一条（恶化例外） |
| 真卡住（错误持续+不编辑） | 1.5s 后报 | 30s 后报；恶化时冷却例外保证增量可见 |

## 6. 预期效果（基于 10-29~11-12 公网真实数据模拟）

对旧版全量 9153 条逐事件模拟（闸门一用 §4.1 中英正则 + 闸门三 120s 冷却；闸门二无服务端数据不可模拟，实际效果只会更好）：

| 阶段 | 事件量 | 占比 |
|---|---|---|
| 基线（旧版全量） | 9153 | 100% |
| 闸门一后（语法豁免 + 纯警告消失） | 1121 | 12.2% |
| 闸门三后（冷却 120s） | **552** | **6.0%** |

幸存 552 条的构成（精准度验证）：`Undefined name \`X\`` 占幸存样本 18.5%，其余为 `Parameter without a default...`、`“return”只能在函数中使用` 等语义/结构类——即**教师看到的基本都是真实卡点**。按人均折算：活跃日 131 条/人 → 约 8 条/人/天，且全部为可解释、可行动的语义错误。LLM 解释调用量同比例下降约 94%。

注意：模拟为事件级保守近似（混合样本事件只要有非语法错误即整条保留；闸门二未计入），真实线上效果优于模拟值。


## 9. 风险与权衡

| 风险 | 评估 |
|---|---|
| Pyright code 取值与假设不符（如语义错无码） | 兜底正则覆盖高频语义消息之外的场景；无码语义错会走正则兜底且不命中语法表 → 正常上报，方向安全。T8 实证后修正 |
| 分发触达失败（重蹈一期覆辙） | 已列为发布先决条件 + 量化验收指标（errors=0 归零）；未触达学生可精确点名（他们仍在发 errors=0 事件，天然可识别） |
| 真卡在语法错误且从不按 F5 的学生不再点亮 | 可接受：跑一次运行即被 run 失败覆盖；且该学生通常会被教师巡视发现 |
| 正则兜底漏匹配新增语法消息 | 保守方向失败：该条走后续闸门，不恶化也不致漏；幸存事件的 codes 字段持续暴露漏网样本供增补 |
| 冷却期抑制导致增量可见性延迟 | 上限 2 分钟，且错误数显著恶化可破例 |
| 残留误报（手误+长时间停顿） | 罕见且此时状态已接近真实「需要关注」，教师成本可忽略 |
